# 安全说明

WinCleanKit 会修改操作系统设置。这里直说它做什么、拒绝做什么，以及怎么退回去。

## 它拒绝碰的东西

以下这些**由代码保证，并由测试套件守护**，不是 README 里的口头承诺：

| 绝不触碰 | 原因 |
|---|---|
| **`hosts` 文件** | 用 DNS 屏蔽遥测是网上最常见的建议，也最容易搞坏东西。它可能让 Windows Update、Microsoft Store 失效，在企业机器上还会打断 VPN 与 SSO 登录。WinCleanKit 完全不碰它。 |
| **你的个人文件** | 除 catalog 里明确列出的缓存路径外，没有任何动作会读取或删除用户目录下的内容。 |
| **你的壁纸** | 桌面壁纸及其转码副本（`TranscodedWallpaper`）保持原样。缓存类动作删除的是已下载的 *Spotlight 广告图*，那是另一回事。 |
| **你的 OneDrive 数据目录** | OneDrive 动作会卸载客户端并阻止重装。如果你的桌面或文档被重定向进 OneDrive，它会**直接拒绝执行**，因为那会让你失去这些目录。 |
| **Windows Update** | `wuauserv`、`UsoSvc`、`BITS` 永不被禁用。安全补丁不是牛皮癣。 |
| **传递优化（`DoSvc`）** | 它是更新加速器，不是遥测。其 P2P 共享可作为独立动作单独关闭。 |
| **Edge 作为浏览器** | 只关掉它的推广标签页和"把我设为默认"弹窗。 |
| **诊断策略服务（`DPS`）** | 保持启用 —— 网络排障依赖它。 |

## 改动如何做到可回滚

在一轮运行的第一个改动之前，引擎会准备一份日志。它为每个动作记录：

- **注册表**：路径、值名、原本是否存在、**精确的旧值**及其类型
- **服务**：名称、原启动类型、原运行状态
- **计划任务**：路径、名称、原状态
- **appx**：被移除的包（这样你知道该重装什么）
- **缓存路径**：被清空的目录

运行结束后生成：

```
桌面\WinCleanKit-<时间戳>\
├── backup.json                机器可读的原始状态
├── Restore-WinCleanKit.ps1    一键还原
└── run.log                    每条动作一行
```

还原脚本会精确恢复注册表值、还原服务启动类型与运行状态、重新启用计划任务。它是**幂等**的 —— 跑两次也无害。

**还原做不到的**：已删除的广告图无法恢复，也不会自动重新下载已卸载的 Store 应用。它会告诉你要重装哪些包。

## 在工作机器上运行之前

1. **先确认单位的规定。** 在受管或加入域的电脑上，部分设置可能由组策略强制下发；你的改动可能在下次策略刷新时被还原，或与 IT 部门的管理策略冲突。WinCleanKit **不会**检测这种情况。
2. **想清楚你在用什么。** 如果你依赖 Game Bar 录屏、手机连接、新版 Outlook、便笺、Microsoft To Do 或 OneDrive，把这些动作留着不动。它们都不在默认勾选里，且都可以单独跳过。
3. **重要机器请先自己做备份。** 系统镜像或还原点，比一份设置日志的保证更强。
4. **读一遍预览。** 预览会显示每个动作的风险等级和原因，花不了三十秒。

## 信任之前先自己验证

```powershell
# 静态校验：catalog 完整性、安全不变量、编码。不做任何改动。
.\tests\Test-Catalog.ps1

# 行为校验：预览不写盘、-Only 是权威列表、dry run 干净。
.\tests\Test-Engine.ps1
```

两套都只读。`Test-Engine.ps1` 只用 `-Plan` 和 `-DryRun`，并断言 dry run 不会创建还原点。

## 报告安全问题

如果你发现某条路径改动了它不该改的东西，或没能还原它记录过的东西，请开 issue 并附上相关动作 id 与 `run.log` 的对应片段。若看起来可被利用，请见 [SECURITY.md](../SECURITY.md)。
